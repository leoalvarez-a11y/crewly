Recorrido paso a paso

Selecciona un paso. Tu posición se conserva mientras navegas por esta página.

Preparar Crewly

  1. Abre el acceso directo de Crewly.
  2. Confirma que carga localhost:8787.
  3. Abre Configuración > General.
  4. Selecciona Español (México).
  5. Define el runtime predeterminado y el máximo de agentes.

Verificar proveedores

  1. Abre Proveedores y costos.
  2. Busca Claude Code y Codex CLI.
  3. Confirma instalación y autenticación.
  4. Revisa la modalidad activa.
  5. No inventes costos cuando diga “No disponible”.

Crear un proyecto

  1. Abre Proyectos.
  2. Pulsa Crear proyecto o New Project.
  3. Asigna nombre y carpeta.
  4. Usa una ruta dentro de Ubuntu WSL, no /mnt/c.
  5. Comprueba la tarjeta y su progreso.

Crear el equipo

  1. Abre Equipos.
  2. Pulsa Nuevo equipo o New Team.
  3. Asigna el proyecto.
  4. Activa modo jerárquico si habrá un líder.
  5. Añade los miembros y guarda.

Configurar agentes

Para cada miembro define rol, runtime, proveedor, modelo, fallback, tokens, presupuesto, skills y memoria.

  • Líder: Claude Code.
  • Developer: Codex CLI con capacidad strong_coding.
  • QA: contexto independiente.
  • Documentación: memoria suplementaria opcional.

Enviar una solicitud

  1. Inicia el equipo.
  2. Abre Chat y elige su canal.
  3. Escribe objetivo, alcance, aceptación y restricciones.
  4. Menciona al equipo si es necesario.
  5. No incluyas secretos.
Ejemplo: “Corrige la validación, agrega una prueba de borde, pide revisión independiente y documenta el resultado”.

Supervisar y verificar

  1. Confirma la entrada en Solicitudes.
  2. Sigue delegaciones en Elementos de trabajo.
  3. Abre la terminal >_.
  4. Comprueba comandos y pruebas reales.
  5. Exige veredicto PASS o FAIL de QA.

Conservar conocimiento

  • Busca decisiones y patrones en Wiki.
  • Revisa la bóveda global, de proyecto o equipo.
  • Conserva memoria y Wiki nativas.
  • Usa Memory Layer externa sólo como suplemento.

Cerrar correctamente

  1. Revisa la respuesta final.
  2. Confirma QA, pruebas y documentación.
  3. Revisa tokens y costos registrados.
  4. Detén el equipo para evitar consumo concurrente.
  5. Consulta Seguridad y conserva la evidencia.

  • Memoria nativa: decisiones, aprendizajes y patrones.

Problemas frecuentes

El runtime está instalado, pero no funciona
Completa el login dentro de Ubuntu WSL2 y confirma en Proveedores y costos que la autenticación sea “Sí”.
El agente no inicia
Revisa el comando CLI en Configuración > General y abre la terminal para ver el error real.
La tarea no aparece
Confirma el canal del equipo en Chat y después revisa Solicitudes y Elementos de trabajo.
El modelo ejecutado no coincide
Revisa selección automática/manual, capability class, fallback y recibo de ejecución.
El costo dice “No disponible”
Ese dato no fue entregado por el proveedor. No debe interpretarse como costo cero.
Una parte aparece en inglés
Algunas etiquetas o contenido de terceros pueden conservarse. Código, rutas, APIs y salida cruda no se traducen.
